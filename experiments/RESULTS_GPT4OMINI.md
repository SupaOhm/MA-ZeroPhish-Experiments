# MA-ZeroPhish on GPT-4o-mini — all experiments (run 2026-09-30, night)

Model `openrouter:openai/gpt-4o-mini-2024-07-18` (provider pinned to OpenAI, temperature 0),
protocol frozen before any call (`exp1_detection/PROTOCOL_GPT4OMINI.md`), data
**DATA_VERSION `b34836430981d74e`** (PhreshPhish own-domain selection, CT v2). Every table
below is generated by `experiments/make_results_tables.py` from `evaluate.py` outputs in
`experiments/results_gpt4omini/`; nothing is typed by hand. Test cases: PhreshPhish test
(all post-cutoff for GPT-4o-mini). Exp 1 uses all 200; Exp 2/4/5/6 use the same balanced
100-case subset (deterministic hash order). Real OpenRouter spend for everything
(pilots, fixes, re-runs, all experiments): **$2.90**.

## Read this first — what the numbers say
1. **The frozen MA-ZeroPhish decides only 10.5% of the 200 test cases on GPT-4o-mini** (it
   abstains with `insufficient` on the rest), so its forced-decision scores are far below
   the baselines. When it decides, it finds the phishing cases (recall 1.000 on decided
   cases), but its few benign decisions include many false alarms (FPR 0.667 on decided
   cases, Exp 1).
2. **Two causes were diagnosed; both are documented and neither was silently changed.**
   - *The calibrated gate stops too early.* The frozen estimator was trained with
     abstaining states excluded from its target, so in thin-evidence states it predicts
     low risk and stops, and the gate then behaves like "no collaboration" (Exp 4: 10% vs
     8% decided). This is demonstrable on calib alone: the gate would stop in 221 of 300
     calib cases, and 53 of those became correct after one more round. A v2 target is
     prepared but NOT adopted (`exp4_collaboration/proposal_v2_stop_failure/`).
   - *The GPT-4o-mini Judge rarely concludes "benign"*, treating permanently unavailable
     retrospective fields (DNS/TLS/WHOIS/hosting) as unresolved gaps even with benign
     support from 4-5 fields. Even full debate decides only 34%. This is a rubric/model
     property; changing the rubric is a decision for the advisor.
3. **What works as designed** (Exp 5, `results_gpt4omini/exp5/audit_disclosure_gpt4omini.txt`):
   no withheld or failed evidence ever became content or `inapplicable`; the Judge cited
   only eligible observations and disclosed every coverage gap and open issue (530 of 530
   decisions each; the other 118 were `finalization_error` abstentions); without browser
   evidence the system abstains instead of guessing (0 decisions); a recoverable acquisition
   failure changed no verdict; conflicting evidence led to abstention; missing evidence
   turned a phishing page benign in 1 case out of 400 degraded runs.
4. **Among the baselines** there is no significant difference (CoT and PhishDebate vs
   single-agent). PhishDebate has the highest recall and by far the highest FPR (0.140).

## Fixes made during the run (all found on calib or pilot data; test untouched)
- Specialists: the model echoed whole evidence lines in the `line` field; the id is now read
  from the leading `[field:Ln]` token and the quote must still be verbatim (commit 00a4f2f).
- Specialist prompt said to report "nothing notable", so benign pages yielded silence; it
  now asks for observations in either direction (commit 62d47a6).
- The CT evidence line `platform_hosted=false` was read as "illegitimate hosting"; every CT
  line is now self-explanatory (commit 62d47a6; new DATA_VERSION).
- Adapter: HTTP 402 stops the run; an HTTP 200 without an answer is an error, never cached
  or scored (commit 10a72c7).
The first calib collection (before these fixes) and its gate are kept in
`runs/superseded_c6a3/` and were never used for any test run.

## Open questions for the advisor
1. Adopt the v2 gate target (abstention = stopping failure)? It would behave like
   fixed-round collaboration (Exp 4: 30% decided, forced F1 0.356), and must be reported as
   decided after the frozen test run.
2. Should the Judge's `def_benign` treat permanently unavailable retrospective fields
   (DNS/TLS/WHOIS/hosting, redirects) as unresolved gaps? Currently it does, which blocks
   benign verdicts on GPT-4o-mini.
3. Run the same protocol on GPT-4o (`PROTOCOL_GPT4O.md`)? Its Judge may behave differently.
4. Not yet run: the supplementary recall study on the 107 excluded platform-hosted pages,
   and the Gemini baselines on the 22 replacement test cases (free quota, after 14:00).

## Consistency checks passed
- Exp 6 ablation3 (no calibrated gate) = Exp 4 fixed-round: identical forced F1 0.356.
- Exp 2 complete / fixed-all = Exp 6 ablation1 (no selection): identical forced F1 0.377.
- The same 100-case MA-ZeroPhish arm gives identical numbers in Exp 2, 4, 5 (base) and 6.

Latency is not comparable across arms: identical requests are served from the shared cache (by design, so arms share the same initial specialist records); tokens are counted in full even when cached.
